# Choosing a Playbooks resource

A Workspace owns shared configuration, funding, and membership. A direct invitation can grant access to a particular resource. Resolve the scope before changing access.

Use a Chat for durable conversational work. Use an Agent for a programmable worker with its own instructions, granted resources, and conversations. Use a Project for authored software with source, a working preview, and an explicit release path to a Site.

Use a Workflow for a repeatable process with steps, decisions, and handoffs. A schedule starts work at a particular time. Use an Artifact when someone needs to retain, inspect, or reuse a versioned HTML experience. A supplied Source, working file, retained Artifact, and running Site have different lifecycles.

Ask what the recipient should get when “share” is ambiguous. Invite grants access to the same resource. Publishing a template offers a reusable version. Remix creates an independent instance. Export delivers supported content outside Playbooks. Releasing to a Site advances a selected production destination.
